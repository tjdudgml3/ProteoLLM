Introduction
The immune system plays a key role in defending the body against pathogens. Innate immunity serves as the first line of defence that responds promptly to conserved pathogen-associated molecular patterns during infection. In contrast, adaptive immunity enables long-lasting memory and antigen-specific responses

Here, we present Immunolyser 2.0, an updated version with expanded functions and improved job management. The new features of Immunolyser 2.0 can be summarised as follows: (i) murine immunopeptidomic data support – Immunolyser 2.0 can now process and analyse murine immunopeptidomic datasets, including peptide-MHC binding prediction; (ii) immunopeptidome-derived
in silico
human and mouse MHC allele typing: A novel algorithm has been developed to assign a predicted MHC-restriction to peptide clusters generated by GibbsCluster in the absence of MHC typing, supporting both human (HLA) and mouse (H-2) alleles
[20]
,

Additionally, users can opt in to receive an email notification upon job submission, containing a unique link that allows them to return to retrieve their results; and (v) an offline version of Immunolyser 2.0 – available as an executable version to enable local processing of larger datasets without limitations on sample size or peptide count. We showcase these new functions using immunopeptidomic datasets from the spleen, liver, and skin of C57BL/6 mice, one of the most commonly used laboratory mouse strains in immunological research
[28]
. With these new features, Immunolyser 2.0 offers a more effective computational pipeline for immunopeptidomic analysis, thereby better supporting research in antigen presentation.

Materials and methods
2.1
Data pre-processing
Similar to Immunolyser 1.0, Immunolyser 2.0 requires input files in CSV (comma-separated values) format. The input files must, at a minimum, have a ‘Peptide’ column listing the peptide sequences. When submitting a job, users can optionally upload a control sample as a CSV file. Once the control file is uploaded, Immunolyser adds a column to the downloadable output files to indicate whether each peptide is present in the control sample. CSV files may also optionally contain an “Accession” column. If this column is detected, Immunolyser will remove any peptides from this column that are labelled as “#DECOY” or “#CONTAM”. Peptide modification annotations will also be removed from the sequence. For example, peptide “A[+ 28.03]TFGVDESNAK” or “A(+28.03)TFGVDESNAK” is processed and reduced to “ATFGVDESNAK”. Input peptides are filtered by length, with peptides of 5–30 amino acids (5–30-mers) used to analyse peptide length distribution and peptide overlap across samples. For class I peptide analysis, 9-mers are used by default to generate the conserved motif by default, but users can also select 8-mers for the conserved motif generation. Alternatively, for class II peptide analysis, 9-mer cores predicted by netMHCIIpan-4.3 are used as input for conserved motif generation. In addition, 8–12-mers and 12–20-mers (corresponding to MHC class I and class II peptides, respectively) are used to run GibbsCluster and MHC binding predictions. 2.2
Using Celery for job and resource management
In Immunolyser 2.0, we deployed Celery
[29]
for queue management and CPU resource allocation, together with Redis
[30]
as the message broker in our Flask
[31]
application. Submitted jobs are processed in a successive fashion by available CPU cores. By default, Celery assigns jobs with one of three statuses: ‘Processing’, ‘Completed’, or ‘Failure’. Upon submission of the job, users will be redirected to a web page where they can monitor the progress of the submitted job.
2.3
Updated Pepscanner module
Pepscanner is an independent module embedded in Immunolyser for the analysis of peptide distribution in source proteins, by extracting the UniProt accessions from the ‘Accession’ column of the input CSV file. In Immunolyser 2.0, we have upgraded the module to accept customised background proteomic data from users in the FASTA format. If no background is provided, Immunolyser 2.0 defaults to using the human proteome downloaded from the UniProt database
[32]
(UP000005640; downloaded on 23rd March 2025). In addition, we enabled an interaction visualisation to demonstrate the distribution of peptides in their source proteins by selecting the protein of interest. In this updated version of the Pepscanner module, we implemented a data visualisation tool, ProtPeptigram, for comprehensive visualization of immunopeptides mapped to their source proteins across multiple experimental conditions, enabling researchers to identify peptide presentation patterns (
e.g.
antigen presentation hotspots), analyse coverage distributions, and compare immunopeptidomes between different samples or treatments. ProtPeptigram retrieves protein sequences from user-provided UniProt FASTA files or the integrated human proteome (UP000005640) reference database. The visualisation algorithm generates:
[1]
a global peptide coverage profile displaying immunopeptide distribution across the entire protein, and
[2]
the optional kernel density estimation algorithm is used to identify presentation hotspots by highlighting regions where the same protein areas are enriched across multiple samples. These high-density regions may indicate immunologically privileged sites within antigen.
2.4
MHC-Typing Prediction
MHC-TP (MHC-Typing Prediction) is a Python-based package for human and mouse MHC allele prediction based on calculating the Pearson Correlation Coefficient (PCC) between every output cluster from Gibbs cluster analysis
[33]
of the input dataset and all deposited reference motifs from NetMHCpan-4.2
[34]
. As MHC-TP is based on Gibbs cluster outputs, each peptide is only allocated on a maximum of one Gibbs cluster and will therefore be considered as having originated from one MHC I allele.
2.5
Updated peptide-MHC binding prediction
Immunolyser 2.0 employs five predictors for peptide-MHC binding prediction in human and mouse immunopeptidomic datasets, including NetMHCpan-4.2
[34]
, MHCpred 3.0
[35]
, and MHCflurry 2.0
[22]
for MHC class I, and NetMHCIIpan-4.3
[19]
and MixMHC2pred-2.0
[21]
,
[26]
for MHC class II. Immunolyser accepts multiple alleles and reports the most confident binding allele from the selected list of alleles for each peptide. Detailed thresholds and parameters for peptide-MHC binding prediction are listed in
Table 2
. Immunolyser 2.0 keeps the majority-voting strategy described in our previous version
[14]
to determine confident peptide binders: i.e., the number of predictors that agree to predict binder > = the number of predictors that agree to predict non-binder. As certain MHC alleles may not be supported by all predictors, the majority-voting strategy is conducted based on the outputs of prediction tools that accept the particular MHC query allele. For example, if an allele is compatible with three predictors and two predict the peptide as a binder, the peptide is qualified as a binder. If the allele is compatible with two predictors and both predict the peptide as a binder, then it is considered a binder.

Results
3.1
Immunolyser 2.0 – an enhanced tool for one-stop immunopeptidomic analysis
A summary of the Immunolyser 2.0 pipeline is demonstrated in
Fig. 1
. Input files, including peptide export from various platforms, along with control files (optional), are submitted via the Initialiser page. Users can specify the species (i.e., human or mouse) and can optionally specify MHC allotypes of interest for binding prediction. Unlike Immunolyser 1.0, which only uses 9-mer peptides to generate conserved motifs and GibbsClustering results, the new version allows users to change the preferred motif length to eight, accommodating for the analysis of some mouse MHC class I allotypes that frequently present 8-mer peptides
[36]
. To limit processing time, the online version of Immunolyser 2.0 has certain restrictions: users can upload up to 10 samples, six MHC allotypes, and a total of 500,000 peptides per job. Upon submission, Immunolyser 2.0 will generate a unique job ID for users to track job status and retrieve results. The job folder will be available for three weeks (subject to change), after which the data files and results are permanently removed. Data files can only be accessed by Immunolyser admin members with server access or by individual users with the direct job link. When submitting a job, users also have the option to provide their email address to receive a job completion notification. Following data pre-processing (
Table 2
and
Fig. 1
C
), Immunolyser 2.0 performs a variety of routine immunopeptidomic analyses, including peptide length distribution, peptide overlap between samples, sequence motif analysis, clustering analysis,
in-silico
MHC typing, and peptide-MHC binding prediction. Our MHC-TP algorithm assists in the prediction of MHC-restriction for each GibbsCluster peptide group through calculating the Pearson Correlation of the observed motif against all deposited MHC motifs available in theNetMHCpan-4.2. Results
, in
Fig. 1
showcases the output generated by using dataset from the study by Pandey et al.
[37]
. The updated Pepscanner module with ProtPeptigram allows users to better visualise peptide coverage of the source protein of interest. For greater flexibility, Immunolyser 2.0 can be deployed as a local application on a shared or private network, facilitating large-scale immunopeptidomic analysis with no restrictions on sample size or the number of peptides analysed. The local version has been fully tested on Windows, Linux, and macOS (Intel and Apple Silicon). We employed Docker to enable a ‘click-and-install’ mode, simplifying software configuration. Users need to download the required third party tools manually, but comprehensive step-by-step instructions are available on our GitHub repository to guide them through the setup process.

Discussion and conclusion
Computational analysis of immunopeptidomics experiments serves as a critical step for assessing data quality and analysing peptide sequence and function. To address this growing need, we developed Immunolyser 1.0
[14]
, which enabled comprehensive analyses of human immunopeptidomic data, including peptide length distribution, peptide sequence pattern and clustering analysis, and peptide-HLA binding prediction. Given the increasing demand for immunopeptidomic analysis, here we introduce Immunolyser 2.0 with a significant upgrade in functionality and stability compared to the first version, thereby advancing the analysis of human and mouse immunopeptidomic data. To our knowledge, Immunolyser (1.0
[14]
and the current 2.0 version), MhcVizPipe
[42]
, and MHCpLogics
[16]
are the only available pipelines designed to facilitate or automate commonly performed steps in immunopeptidomic analysis. MHCpLogics (MATLAB-based) provides the flexibility in deconvoluting immunopeptidomic datasets based on MHC allotypes
[16]
, while only MhcVizPipe offers an offline version for Linux or Linux virtual environment, requiring users to manually configure and install the dependencies, such as NetMHCpan and GibbsCluster. Compared to these tools, Immunolyser 2.0 demonstrates a wide array of analytical features, such as the newly developed MHC-TP algorithm for MHC-typing and restriction prediction of peptide clusters even for samples of unknown MHC type, ProtPeptigram visualisation for peptide distribution and source protein analysis, efficient job management, and a streamlined Docker-based setup for Immunolyser deployment. A detailed comparison of available platforms is found in
Table 3
. While genetic HLA typing remains the gold standard and can provide high resolution HLA allele information, this information is not always available. Our MHC-TP module can provide reliable information on potential HLA-restriction. The obvious limitation of MHC-TP is that alleles with highly similar motifs cannot be resolved; we therefore implemented a default mode where the 40 globally most prevalent HLA alleles from each MHC I locus are employed as high likelihood restriction elements. PCC values generated by MHC-TP and alternate explanations for the MHC I source allele of a Gibbs cluster motif can be accessed and reviewed by the user.

Overall, immunolyser 2.0 introduces significant improvements in immunopeptidomics data analysis, offering a more streamlined and user-friendly experience. This version lays a strong foundation for future expansion, e.g. the modular design of Immunolyser 2.0 enables potential integration of further tools as they become available. We believe this release will server as a robust and extensible platform for routine immunopeptidomic data analysis.
